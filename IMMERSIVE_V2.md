# BELOW THE SURFACE — IMMERSIVE EDITION / Revision 2
## Historical design brief (archived)

> **Historical design brief (archived):** Preserved as the Revision 2 creative specification that introduced the spatial ocean descent, expedition index, depth rail, and specimen lab. For the live production architecture, security model, and CMS operations, see [README.md](./README.md), [docs/operations.md](./docs/operations.md), and [docs/deployment.md](./docs/deployment.md).

Builds on [DESIGN.md](./DESIGN.md), superseding its conservative motion, static hero, conventional horizontal navigation, and repeated contour backgrounds while preserving content integrity, accessibility, localization, SEO, and security constraints.

## Creative direction
Build an interactive expedition, not a dark portfolio decorated with ocean graphics. Reference experiences: Abyssal, The Sea We Breathe, Aquatilis Expedition. Use their cinematic framing, immersive transitions and unconventional navigation as principles, not copied assets/layouts. Do not claim to have inspected live references if inaccessible. Design around a real person: software engineering, product experimentation, diving and curiosity. Use actual verified personal photographs and project assets, not invented documentary evidence. The primary narrative is a builder's mind, not an aquarium or diving business.

## 1. Hero: the descent (mandatory showpiece)
- Full-bleed 100svh composition, asymmetric oversized type and a single continuous ocean-inspired spatial scene. Identity and profession visible immediately, with direct Work and CV access. No generic two-column hero with decorative SVG on right.
- Build a custom procedural scene: layered volumetric-looking light, suspended particles, depth fog, subtle caustic-like patterns and bathymetric geometry. Prefer a lightweight shader/canvas or isolated React Three Fiber scene if justified by actual stack. Use a deterministic static poster fallback; no external stock video dependency. Real personal underwater photo may become the hero texture if verified and visually suitable.
- Pointer movement affects the scene via damped parallax, never moves reading text. On scroll, camera descends, light fades, geometry shifts in perspective, and the next chapter emerges from the same environment. Establish a distinct surface-to-depth reveal within first two viewport heights; no scroll trapping or forced intro. Native wheel/touch/keyboard scrolling works. No mandatory click-to-enter.
- Hero is recognizable in a still screenshot but meaningfully different at 0%, 50%, 100% of transition. No simple fade/translate-only substitute. The scene must visually respond to input; static particles alone fail.

## 2. Navigation: expedition instrument
- Remove the conventional centered row of links, rounded nav capsule, and generic AI/chat button treatment. Desktop: wordmark top left; compact index control top right with chapter number and label; interactive depth rail at edge with labeled stops on focus/hover. Recruiter/CV is a persistent, legible shortcut, not hidden in the index. Avoid three competing floating docks.
- Index opens a full-screen editorial chart: numbered chapters, large type, corresponding depth markers, current chapter and optional real visual preview. Hover/focus previews chapter atmosphere; click navigates directly and closes. Escape, focus trap, focus return, keyboard and screen reader labels required. No hover-only information.
- Rail follows real chapter progress, clickable stops, active marker, direct navigation, no fake readings. Secondary routes have an obvious return and index. Mobile uses a small top bar and a thumb-accessible index control; no crowded fixed rail. Test 320px and Turkish text.
- Existing AI assistant, if present, becomes a restrained Lab instrument integrated into chapter design, with a discoverable index entry; retain functionality, privacy, error handling and keyboard access. Do not put a generic floating purple chatbot on every page. Do not imply a live model or capability not present.

## 3. Chapters: distinct scenes, shared grammar
- Human: personal field journal with a real photograph, handwritten-style annotations only if legible, staggered editorial composition. Reveal annotations as image enters viewport. No generic About card.
- Selected Work: 2–4 verified flagship projects, each a large cinematic plate with distinct art direction inside consistent framing. On scroll project image and typography move at different rates, next plate emerges via a controlled mask or depth transition. Click opens a shareable project page. Provide static stacked alternative on mobile/reduced motion. No mandatory horizontal scroll.
- Lab: interactive experiment index rather than repeated card grid. Keyboard/touch selectable rows update a preview pane, showing verified project artifacts or abstract project-specific diagram. Link to full archive. Assistant can sit here as an actual working experiment.
- Engineering: interactive architecture diagram based on actual project code/data, with selectable nodes and explanatory detail. If architecture evidence missing, choose verified stack categories and clearly distinguish conceptual illustration. Never invent a system diagram as factual.
- Journey: vertical expedition log with verified dates and contextual visuals. Contact: calm horizon, direct contact links and actual form, return-to-surface control. No animation blocking form.
- Every chapter has its own compositional signature, image crop, density and motion. Reuse palette, typography and small instrument labels, not identical containers or repeated contour wallpaper. At least three materially distinct interactive sequences: descent, project plate transition, index/lab exploration.

## 4. Asset integration and archive
Audit ALL previous assets, Git baseline, public directories and existing Firebase content references. Inventory real logos, photos, screenshots, links and missing files. Never delete or silently omit existing projects. A logo is not a screenshot. Do not invent interface screenshots, usage metrics or personal photos. If only logo exists, design an original editorial project plate using logo on a controlled paper/ink field with project-specific framing, restrained texture and metadata outside the art. Label conceptual graphics appropriately. Never recolor logos indiscriminately; use neutral backplates and contrast-aware variants. Preserve aspect ratio, object-fit contain for logos, deliberate crop for photos, no caption overlap. Use consistent image aspect ratios, margins and optical alignment. Avoid random legacy card CSS and arbitrary gradients. Archive is a typographic index with filter controls and cohesive preview plates; project details use same design grammar with actual evidence. Make a reusable asset presentation component with explicit variants (logo/photo/screenshot/diagram) and fallbacks. Inspect every project in both languages and mobile. If AKAR, CallWhisper or 42 Istanbul are absent from verified site data, report missing material rather than publishing invented content or changing Firebase without approval.

## 5. Motion implementation
Use actual scroll progress (GSAP/ScrollTrigger or equivalent if justified), one coordinated scene lifecycle, requestAnimationFrame only when necessary, resize and route cleanup, DPR cap around 1.5–2, adaptive particle density and offscreen pausing. Motion must be intentional and observable. Avoid scroll hijacking, custom cursor replacing native cursor, endless text animation, gratuitous magnetic controls, mandatory sound, multiple competing canvases. Reduced motion and no-WebGL fallback retain layout, content and navigation; touch has no dependency on pointer. Avoid delaying LCP text for canvas. Keep page accessible and performant; measure before/after rather than claim targets achieved. Lazy-load heavy modules; do not globally load 3D on archive/recruiter/admin.

## 6. Preserve and review functional changes
Previous agent reported removal of theme toggle, PDF popup replacement, Firebase refresh every 60 seconds instead of live, web API contact submission and recruiter redirect. Treat these as unapproved changes requiring explicit review; preserve or restore original functional semantics where feasible, flag tradeoffs rather than silently accepting them. Audit contact security rules, validation and error states; use emulator/mocks or authorized test, never submit a real message without permission. Correct obvious spelling only if verified; flag conflicting education dates. Keep admin isolated. Do not edit production data.

## 7. Verification and visual gates
Capture fresh screenshots (wait for repaint, verify actual viewport and route) at 320/390/768/1024/1440/1920. Capture hero at start/mid/end, index open, project plate transitions, lab selected states, archive, all representative asset types, contact, recruiter; test all routes, keyboard, touch, reduced motion, no WebGL, localization, navigation, links and contact mock. Record short screen video or sequential frames if tools permit: static screenshots cannot prove interaction. Run build, lint, typecheck, tests and Lighthouse if available. Report measured results and blockers, including unavailable browser capabilities. Inspect rendered screenshots and iterate; do not stop at plan or self-assigned score.

Acceptance rubric /100: immersive interaction and distinctive showpiece 30; originality and navigation 20; asset integration and editorial composition 20; personal identity and verified content 10; accessibility/responsive 10; performance/functionality/maintainability 10. Target 85+, but hard gates override score: no conventional nav reskin, no static-only hero, no mismatched legacy cards, no missing existing content, no interaction regressions, no invented facts. If a gate fails, continue improving or disclose exact blocker. Deliver actual implementation, screenshot/video evidence, file summary, tests, remaining risks and decisions requiring approval. Do not deploy.
